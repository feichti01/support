Report a problem and review reports

Support requests and bug reports go through the public issue list in the feichti01/support repository. Homing reports carry the label homing. The list is a short English extract of the publicly shareable items and not a complete status source.

  • View the public bug list Open, publicly mirrored Homing bug fixes on GitHub.
  • Create a new support report Opens a new GitHub issue; a GitHub account is required.
  • Private request by email For questions involving personal data, or if you prefer not to use a GitHub account.
  • Report a security vulnerability By email with the subject homing security, please, not in public.

Homing is maintained by one person in their spare time. You will normally hear back within seven days.

What to include in a report

  • macOS version and chip (Apple menu > About This Mac).
  • Homing version (Finder > select /Applications/Homing.app > Get Info) and where you got it: Mac App Store or the .pkg from GitHub.
  • Your headphones model.
  • What you clicked and what happened. If possible, the relevant lines from Console.app filtered for Homing.

Never post passwords, certificates or other people's device addresses in public issues.

Download and source code

  • Homing on the Mac App Store Free, with automatic updates through the App Store.
  • Signed and notarized installer Direct .pkg download from the releases repository.
  • Source code on GitHub Open source under the MIT License.

Homing requires macOS 13 Ventura or later. Only the latest version receives fixes.
