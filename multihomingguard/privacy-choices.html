Datenschutz-Einstellungen für MultihomingGuard

Privacy Choices: was Sie auf Ihrem Mac selbst steuern können.

  • Deutsch
  • English

Deutsch

Stand: 19. September 2026

Kurzfassung: MultihomingGuard erhebt keine personenbezogenen Daten, verwendet kein Tracking, keine Analyse und keine Werbung und kontaktiert keinen Server des Entwicklers. Es gibt daher nichts, dem Sie zustimmen oder widersprechen müssten, kein Konto zum Löschen und keine Daten, die Sie beim Entwickler anfordern könnten. Diese Seite listet, was Sie auf Ihrem Mac selbst kontrollieren.

1. Standortfreigabe für den WLAN-Namen

macOS gibt den Namen des verbundenen WLANs nur an Apps mit Standortfreigabe heraus. MultihomingGuard fragt beim ersten Öffnen des Menüs nach „Beim Verwenden der App“. Sie können ablehnen: Dann fehlt im Menü nur der Netzwerkname; Band, Kanal und der Schutz selbst funktionieren unverändert. Die Freigabe ändern Sie jederzeit unter Systemeinstellungen > Datenschutz & Sicherheit > Ortungsdienste > MultihomingGuard. Die App liest keinen Standort und speichert den Netzwerknamen nicht.

2. Einstellungen

Über ⚙ im Menü gibt es eine lokale Einstellung: iPhone-Tethering bei LAN erlauben. Der Hintergrunddienst speichert sie in /Library/Preferences/com.feichtiq.multihomingguard.plist. Gibt Ihre Organisation den Wert per Konfigurationsprofil vor, ist der Schalter ausgegraut. Weitere Einstellungen oder ein Verlauf werden nicht gespeichert; es gibt keinen Keychain-Eintrag für Benutzer.

2a. Updateprüfung

Unter ⚙ steht Automatisch nach Updates suchen. Eingeschaltet fragt die App einmal täglich www.feichtiq.com nach einer neuen Version – ohne Gerätekennung. Ausgeschaltet bleibt nur „Jetzt prüfen“ auf Ihren Klick. Installiert wird in beiden Fällen erst, wenn Sie „Update installieren“ wählen; die Zeitpunkte der Prüfungen stehen in der Diagnose.

3. Protokolle und Diagnose

Der Dienst schreibt keine eigenen Protokolldateien. Statusmeldungen gehen in das macOS-Systemprotokoll (Subsystem com.feichtiq.multihomingguard), das macOS selbst nach eigenen Regeln verwirft. Zusätzlich hält der Dienst die letzten 300 Entscheidungen im Arbeitsspeicher; Diagnose im Menü legt sie in die Zwischenablage. Sie enthalten Zeitstempel, Adapter- und Dienstnamen, den Verbindungszustand, lokale IP- und DNS-Server-Adressen sowie Pausen-Ereignisse – keine WLAN-Namen, Passwörter oder Benutzernamen. Nichts davon wird übertragen; Sie entscheiden, ob Sie den Text einer Supportmeldung beifügen. Ein Neustart des Dienstes leert den Speicher.

4. Pause und Support-Code

Eine Pause des Schutzes (versteckter Admin-Bereich, ⌥ beim Öffnen des Menüs) wird mit Zeitpunkt, Dauer, Weg (Administrator oder Support-Code) und Prozess-ID der anfragenden App im Systemprotokoll vermerkt. Der Support-Code wird lokal aus der Seriennummer des Macs, einer Zufallszahl und einem nur dem Dienst und dem Support bekannten Schlüssel berechnet; die Seriennummer verlässt den Mac nur, wenn Sie sie dem Support am Telefon nennen. Der Schlüssel liegt unter /Library/Application Support/MultihomingGuard/support.key, lesbar nur für das System.

5. Vollständig entfernen

In verwalteten Umgebungen entfernt die Geräteverwaltung die App. Von Hand im Terminal (Administratorrechte nötig):

sudo launchctl bootout system/com.feichtiq.multihomingguard.daemon
sudo launchctl bootout gui/$(id -u)/com.feichtiq.multihomingguard.menu
sudo rm -f /Library/LaunchDaemons/com.feichtiq.multihomingguard.daemon.plist /Library/LaunchAgents/com.feichtiq.multihomingguard.menu.plist
sudo rm -f /usr/local/libexec/MultihomingGuardDaemon /Library/Preferences/com.feichtiq.multihomingguard.plist
sudo rm -rf /Applications/MultihomingGuard.app "/Library/Application Support/MultihomingGuard"
sudo pkgutil --forget com.feichtiq.multihomingguard

Optional die Standortfreigabe unter Ortungsdienste entfernen. Danach ist nichts von MultihomingGuard mehr auf Ihrem Mac vorhanden; schalten Sie WLAN bei Bedarf in den Systemeinstellungen wieder ein.

6. Supportseite und GitHub

Diese Seite setzt keine Cookies und lädt keine externen Skripte. GitHub Pages protokolliert IP-Adressen zu Sicherheitszwecken; das können Sie nur durch Nichtaufrufen der Seite vermeiden. Öffentliche Issues können Sie in Ihrem GitHub-Konto selbst bearbeiten oder löschen. Für alles andere genügt eine E-Mail an christian@feichti.at.

Privacy choices for MultihomingGuard

Effective: September 19, 2026

Summary: MultihomingGuard collects no personal data, uses no tracking, analytics or advertising and never contacts a developer server. There is therefore nothing to consent to or object to, no account to delete and no data to request from the developer. This page lists what you control on your own Mac.

1. Location permission for the Wi-Fi name

macOS discloses the name of the connected Wi-Fi network only to apps with Location permission. MultihomingGuard asks for "While using the app" when the menu is first opened. You may decline: only the network name is then missing from the menu; band, channel and the guard itself work unchanged. Change the permission at any time under System Settings > Privacy & Security > Location Services > MultihomingGuard. The app reads no location and does not store the network name.

2. Settings

⚙ in the menu offers one local setting: Allow iPhone tethering while on LAN. The background service stores it in /Library/Preferences/com.feichtiq.multihomingguard.plist. If your organization sets the value through a configuration profile, the switch is greyed out. No further settings or history are stored; there is no Keychain item for users.

2a. Update check

⚙ offers Check for updates automatically. When on, the app asks www.feichtiq.com once a day for a new version – without any device identifier. When off, only "Check now" remains, on your click. Either way nothing is installed until you choose "Install update"; check times are listed in the diagnostics.

3. Logs and diagnostics

The service writes no log files of its own. Status messages go to the macOS unified log (subsystem com.feichtiq.multihomingguard), which macOS discards by its own rules. In addition the service keeps its last 300 decisions in memory; Diagnostics in the menu puts them on the clipboard. They contain timestamps, adapter and service names, the connection state, local IP and DNS server addresses and pause events – no Wi-Fi names, passwords or user names. Nothing is transmitted; you decide whether to attach the text to a support request. Restarting the service clears the buffer.

4. Pause and support code

A pause of the guard (hidden admin area, ⌥ while opening the menu) is recorded in the unified log with time, duration, path (administrator or support code) and the process ID of the requesting app. The support code is computed locally from the Mac's serial number, a random challenge and a key known only to the service and to support; the serial number leaves the Mac only if you read it to support on the phone. The key is stored at /Library/Application Support/MultihomingGuard/support.key, readable by the system only.

5. Remove completely

In managed environments device management removes the app. By hand in Terminal (administrator rights required):

sudo launchctl bootout system/com.feichtiq.multihomingguard.daemon
sudo launchctl bootout gui/$(id -u)/com.feichtiq.multihomingguard.menu
sudo rm -f /Library/LaunchDaemons/com.feichtiq.multihomingguard.daemon.plist /Library/LaunchAgents/com.feichtiq.multihomingguard.menu.plist
sudo rm -f /usr/local/libexec/MultihomingGuardDaemon /Library/Preferences/com.feichtiq.multihomingguard.plist
sudo rm -rf /Applications/MultihomingGuard.app "/Library/Application Support/MultihomingGuard"
sudo pkgutil --forget com.feichtiq.multihomingguard

Optionally remove the Location permission under Location Services. Nothing of MultihomingGuard remains on your Mac afterwards; turn Wi-Fi back on in System Settings if needed.

6. Support site and GitHub

This page sets no cookies and loads no external scripts. GitHub Pages logs IP addresses for security; the only way to avoid that is not to visit the page. You can edit or delete your own public issues in your GitHub account. For everything else, an email to christian@feichti.at is sufficient.
